# 从零发布你的第一个 ZCode 插件

> 这是 ZCode 插件开发系列的第一篇，带你从一个空文件夹开始，做出一个能安装、能运行、能发布给别人的插件。
>
> 全程只需要会写 JSON 和 Markdown，**不需要改 ZCode 本体，也不需要搭任何开发环境**。
>
> 读完这篇之后：
> - 遇到具体问题 → 按[《ZCode 插件开发实战指南》（速查手册）](02-ZCode插件开发实战指南.md)的症状表查
> - 想理解为什么会有这些坑、做出更可靠的插件 → 看[《Agent 插件开发通用方法论》](03-Agent插件开发通用方法论.md)

---

## 你将做出什么

一个叫 `hello-plugin` 的最小插件，只包含两个组件：

- **1 条命令 `/hello`**：用户输入 `/hello` 时**必然执行**
- **1 个技能 `greet`**：当用户想要问候语时，AI **可能**自动调用

用它走完整条发布链路：**本地写 → 本地装 → 本地测 → 推到 GitHub → 让别人能安装、能收到更新**。

预计耗时：30~60 分钟。

---

## 开始前：三个概念

### 概念一：插件就是一个文件夹

根目录放一份清单 `plugin.json`（唯一必需），其余组件目录全部按需添加：

```
hello-plugin/
├── .zcode-plugin/
│   └── plugin.json    # 清单（唯一必需）
├── commands/          # 斜杠命令：每个命令一个 .md 文件
├── skills/            # 技能：每个技能一个子目录，含 SKILL.md
├── agents/            # 子智能体定义：每个一个 .md 文件
├── hooks/hooks.json   # 钩子：在特定事件时机自动执行
└── .mcp.json          # MCP 服务声明：接入外部工具
```

ZCode 会自动识别目录里有什么组件，不需要在清单里逐一登记每个文件——只要把 `commands`、`skills` 这类目录路径写进 `plugin.json` 即可。

> 入门建议：**先只用"技能 + 命令"把全流程跑通**，子智能体、Hook、MCP 等熟练之后再加。

### 概念二：Skill 与 Command 的区别（最重要的一个认知）

| | Skill（技能） | Command（命令） |
|---|-------|---------|
| 触发方式 | AI 根据 description **自动匹配** | 用户输入 `/` **显式调用** |
| 可靠性 | **不保证触发**，是概率事件 | **100% 触发** |
| 适用场景 | 辅助性、上下文增强 | 强制流程、固定操作 |

这是实测结论，不是文档措辞：同一个技能的 description 改了四五轮（加触发词、按优先级排列、写禁止事项），AI 照样可能在用户明确说了触发语时无视技能直接干活。**description 写得再好也只是提高概率，不是开关。**

**结论：需要"必须执行"的流程，用 Command；辅助性的能力，用 Skill。** 两个都做，让用户自己选可靠性等级。

### 概念三：插件市场（marketplace）是分发单位

插件不是单独安装的，而是通过"插件市场"分发——一个市场就是一个仓库根目录下的 `marketplace.json`，里面列出若干插件及各自的位置。你添加一个市场来源后，就能浏览安装它发布的所有插件。

本教程会先建一个**本地市场**用来测试，第 3 步再把它推上 GitHub 变成真正的线上市场。

## 第 1 步：创建插件骨架

找一个工作目录（任意位置），按下面的结构创建文件：

```
my-first-market/              # 市场根目录（第 2 步添加市场时指向这里）
├── marketplace.json          # 市场清单
└── hello-plugin/             # 插件本体
    ├── .zcode-plugin/
    │   └── plugin.json
    ├── commands/
    │   └── hello.md
    └── skills/
        └── greet/
            └── SKILL.md
```

### 文件 1：plugin.json（插件清单）

```json
{
  "name": "hello-plugin",
  "version": "0.1.0",
  "description": "我的第一个 ZCode 插件",
  "author": { "name": "your-name" },
  "license": "MIT",
  "skills": "skills",
  "commands": "commands"
}
```

必改点：

| 字段 | 规则 |
|------|------|
| `name` | 必须匹配 `^[a-z0-9][a-z0-9._-]{0,127}$`（**小写字母或数字开头**，可含 `.` `_` `-`） |
| `version` | 缺省 0.0.0。从现在起养成习惯：**每次改动都更新它**（第 4 步你会知道为什么） |

### 文件 2：commands/hello.md（斜杠命令）

```markdown
---
description: 打一声招呼，验证插件已正常安装
argument-hint: "[称呼，可选]"
---

请向用户问好。如果 $ARGUMENTS 非空，用传入的称呼（$ARGUMENTS）称呼对方；否则称呼"世界"。最后补一句：你的第一个 ZCode 插件已经正常工作了。
```

说明：

- 命令名 = 文件名（`hello.md` → `/hello`），必须匹配 `^[a-z0-9][a-z0-9_:-]{0,63}$`
- `description` 必填，显示在 `/` 命令列表里
- 正文中的 `$ARGUMENTS` 代表用户在命令后面输入的全部参数（`/hello 老王` → `$ARGUMENTS` = `老王`）

### 文件 3：skills/greet/SKILL.md（技能）

```markdown
---
name: greet
description: 当用户想要生成问候语、写欢迎词、打招呼时使用此技能。
when_to_use: 用户说"帮我写个问候语"、"给新同事写欢迎词"时触发。
---

# Greet 技能

1. 根据对方身份选择正式或轻松的语气
2. 生成 2~3 句问候语，直接输出给用户
```

- `description` 是 AI 决定"要不要用这个技能"的唯一依据，**写清"什么时候用"**，最长 1024 字符
- `when_to_use` 补充触发时机，与 description 呼应

> ⚠️ **格式红线**：`SKILL.md` 和命令 `.md` 的 frontmatter（`---` 包裹的那段）**必须从文件第一行开始**。第一行之前哪怕多一个 HTML 注释、一行横幅、一个空格开头的 BOM，整个文件都会解析失败，且报错信息往往不指向真实原因（比如只报"缺少 frontmatter"）。

### 文件 4：marketplace.json（市场清单，放在市场根目录）

```json
{
  "name": "my-first-market",
  "description": "我的本地测试市场",
  "plugins": [
    {
      "name": "hello-plugin",
      "source": "./hello-plugin",
      "description": "我的第一个插件",
      "version": "0.1.0"
    }
  ]
}
```

`source` 是相对市场根目录的路径。发布到 GitHub 后这份文件原样使用。

## 第 2 步：在本地安装测试

### 2.1 添加本地市场

1. 打开 ZCode（**先打开一个工作区**，插件页需要工作区才可用）
2. **设置 → 插件**，点右上角 **创建 → 添加插件市场**
3. 选择**本地目录**，指向 `my-first-market` 文件夹（路径必须真实存在）
4. ZCode 会先校验市场，通过后它发布的插件出现在 **个人** 分段
5. 找到 `hello-plugin`，点 **安装**（新装插件默认启用）

### 2.2 验证两种触发方式

**新建一个会话**，然后：

1. 输入 `/hello` → 应该立即执行并问好（命令是必然触发的）
2. 输入 `/hello 张三` → 问好时应该称呼"张三"（`$ARGUMENTS` 生效）
3. 对 AI 说"帮我写一段欢迎新同事的欢迎词" → 观察它是否调用 greet 技能（可能触发、也可能不触发——亲身体验一下"自动触发是概率"这件事）

### 2.3 改代码后的迭代流程

技能、命令的注册表缓存在 ZCode 进程内存里，改了源文件不会立即生效。每次迭代：

1. 把 `plugin.json` 和 `marketplace.json` 里的 `version` **两处都 +0.0.1**
2. 插件页 → 搜索框上方**齿轮图标**（市场源面板）→ 找到你的市场 → **刷新该市场**
3. **管理已安装** 页面 → **检查更新** → 更新插件
4. 必要时新建会话

> 只改文件不改版本号，"检查更新"永远不会提示有新版本——版本对比完全基于 version 字段。所以从第一个插件开始就养成"改动即升版本"的习惯。

## 第 3 步：发布到 GitHub

### 3.1 仓库结构

把 `my-first-market` 整个目录作为一个 Git 仓库推上去。**marketplace.json 必须在仓库根目录，插件放在二级子目录**：

```
your-repo/                    # GitHub 仓库根
├── marketplace.json          # ⚠️ 必须在根目录
├── README.md
└── hello-plugin/             # 插件在二级子目录
    └── ...
```

```bash
cd my-first-market
git init
git add .
git commit -m "feat: 我的第一个 ZCode 插件"
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> ⚠️ 两个最常见的发布报错，都源于 marketplace.json 放错位置：
> - 把 marketplace.json 放进插件子目录 → `Marketplace manifest not found`
> - 把插件直接放在仓库根目录（marketplace.json 反而放进了子目录）→ 同样报错
>
> 记住口诀：**市场清单在根，插件在二级，source 用 `./插件名` 指向。**

### 3.2 让别人安装

任何人（包括你自己换台机器）都可以：

1. ZCode → **设置 → 插件** → **创建 → 添加插件市场**
2. 选择 **Git 仓库**，粘贴你的仓库地址（如 `https://github.com/you/your-repo.git`）
3. 在 **个人** 分段找到插件 → **安装**

仓库做大了以后，同一个 `marketplace.json` 的 `plugins` 数组里可以继续追加插件，一个仓库就是一个市场。

## 第 4 步：发新版，让用户收到更新

### 先记住一个事实：ZCode 不会自动更新插件

你推了新版本，用户本地依然是旧版，必须手动触发更新。而且更新是**三步流程，一步都不能少**：

1. **刷新市场缓存**：插件市场页 → 齿轮图标 → 找到你的市场 → **刷新该市场**
2. **检查更新**：管理已安装页面 → **检查更新**
3. **安装新版本**

> 跳过第 1 步直接检查更新，ZCode 用的是本地缓存的市场清单（旧版本号），永远提示"已是最新"。

### 发版清单（每次发布照着过一遍）

- [ ] 插件的 `plugin.json` 改了 `version`
- [ ] 仓库根 `marketplace.json` 里该插件条目的 `version` 也改了（**两处必须一致地改**）
- [ ] commit + push
- [ ] 用你自己的 ZCode 走一遍三步更新流程，确认能收到新版本

> ⚠️ **版本双同步**是最容易踩的坑：「最新版本」取自 marketplace.json 里该插件条目的 version，「已安装版本」取自插件自身的 plugin.json。只改一边，要么用户收不到更新提示，要么版本号对不上出现异常。
